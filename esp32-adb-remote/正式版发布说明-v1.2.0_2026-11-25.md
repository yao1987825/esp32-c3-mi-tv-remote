# 正式版发布说明 v1.2.0（2026-11-25）

## 一句话总结

**修好了中间那个「确认/OK」键在电视上完全无效的问题**，按键收敛成
**电源开关机 / 上下左右 / 确认 / 返回 / 音量加减**，删掉了没用的语音键，
并且**去掉了「电源（长按）」**（长按 = 彻底关机 = 唤不醒）。

---

## 一、确认键（OK）在电视上无效 —— 根因与修复

### 症状

板子日志里按键正常发出（`pressSpecial: key=0 connected=YES`），电视**毫无反应**，
而上下左右、音量、电源全都正常。

### 根因（三步实测定位）

**第 1 步：电视给遥控器用的 keylayout 文件**

```
adb shell dumpsys input | grep -A4 '小米蓝牙语音遥控器'
  → KeyLayoutFile: /system/usr/keylayout/Vendor_2717_Product_32b8.kl
```

同一个文件也管着我们板子（「MI Remote」）。把它拉下来：

```powershell
adb shell cat /system/usr/keylayout/Vendor_2717_Product_32b8.kl
```

```
key 158   BACK
key 127   MENU
key 108   DPAD_DOWN
key 103   DPAD_UP
key 172   HOME
key 102   HOME
key 105   DPAD_LEFT
key 106   DPAD_RIGHT
key 115   VOLUME_UP
key 114   VOLUME_DOWN
key 116   POWER
key  28   DPAD_CENTER      ← 中间键必须是这个
key  88   F12
```

**第 2 步：我们在电视上实际发出的键码**

```powershell
adb shell getevent -lt          # 一边听一边按板子的键
```

```
/dev/input/event4: EV_MSC  MSC_SCAN  000c0041
/dev/input/event4: EV_KEY  KEY_SELECT DOWN          ← Enter 键
/dev/input/event4: EV_MSC  MSC_SCAN  000c0042
/dev/input/event4: EV_KEY  KEY_UP     DOWN          ← Up 键
```

`000c0041` = 消费页 usage 0x41（"Menu Pick"）。**电视内核把它认成了 `KEY_SELECT`(353)**，
而上面那个 .kl 文件里**没有 353 这一行** → 这个键被内核直接丢掉 → 电视毫无反应。

其它键（0x42/0x43/0x44/0x45/0xE9/0xEA）分别被认成 KEY_UP / KEY_DOWN / KEY_LEFT /
KEY_RIGHT / KEY_VOLUMEUP / KEY_VOLUMEDOWN，**全都在 .kl 里**，所以它们一直正常。

**第 3 步：原装遥控器是怎么做的**

电视上能直接读到原装的 HID 报告描述符：

```powershell
adb shell cat /sys/class/hidraw/hidraw1/device/report_descriptor
```

原装的键盘报告数组**第一个 usage 就是 0x28（Enter）**：

```
05 01 09 06 a1 01 85 01
05 07 19 e0 29 e7 15 00 25 01 75 01 95 08 81 02   ← 8 个 modifier
95 01 75 08 81 01                                  ← reserved
95 05 75 01 05 08 19 01 29 05 91 02               ← LED
95 01 75 03 91 01                                  ← padding
95 06 75 08 15 28 25 fe 05 07 19 28 29 fe 81 00  ← ★ usage 0x28 = Enter
```

`dumpsys input` 的 RecentQueue 里也留着原装按中间键的记录：

```
KeyEvent(deviceId=6, keyCode=23, scanCode=28)
                 ↑ DPAD_CENTER   ↑ KEY_ENTER
```

### 修复

确认键改成走**键盘报告 usage 0x28 (Enter)**，和原装遥控器一模一样。

**不用改报告描述符**（所以不用重新配对）：我们的描述符里键盘段和原装**逐字节相同**，
只是 Report ID 不同（我们 0x02 / 原装 0x01），Report ID 不影响按键翻译。

改动：

- `ble_mi_remote.h`：新增 `HID_USAGE_ENTER = 0x28` 和 `pressEnter()` 声明
- `ble_mi_remote.cpp`：新增 `BleMiRemote::pressEnter()`；`pressSpecial()` 里
  `SPECIAL_MENU_PICK` 走键盘报告而不是消费页位图

「确认」在电视界面里 = DPAD_CENTER；在播放界面同一个键就是播放/暂停，
所以一个键同时满足「可暂停、确认」。

## 二、按键收敛

### 暴露到 HA 的按键（9 个）

`ble_mi_remote:` 新增 `buttons:` 白名单选项，YAML 里只列要暴露的键：

```yaml
  buttons:
    - Enter        # 确认
    - Up
    - Down
    - Left
    - Right
    - Power
    - Back         # 返回
    - Volume Up
    - Volume Down
```

**组件本身的能力一点没少** —— 没列出来的键（主页、停止…）照样能用
`ble_mi_remote.press: code: "Android TV"` 这种 action 发出去，只要在 `button:` 那段
加一个模板按钮就行。加回「主页」只要两行：

```yaml
  - platform: template
    name: "TV Home"
    id: tv_home
    on_press:
      - ble_mi_remote.press:
          id: mi_remote
          code: "Android TV"
```

### 删掉「电源（长按）」按钮 ⚠ 重要

实测这台 MiTV4-ANSM0 的电源键行为：

| 操作 | 电视的反应 | 后果 |
|---|---|---|
| **短按** | 关屏待机 | 还能被 BLE 唤醒，板子照常连得上 |
| **长按** | **彻底关机** | 电视的 BLE 主机也停了 → **任何 BLE 唤醒都唤不醒**（连原装遥控器都不行），板子从此再也连不上这台电视，只有拔电源才能恢复 |

所以「长按电源」这个按钮必须删掉，只留短按的 `Power`。

### 删掉语音键

`Voice`(6) 和 `Voice2`(17) 都用消费页 usage 0xCF，本来就是重复键。
板子上没有麦克风，点了只会弹「找不到语音输入」，已从组件里删除。

> ⚠ 删条目时**其余键的 CONF_VALUE 一律不能重编号** —— CONF_VALUE 就是描述符里
> 消费页位图的位号，重编号会让所有键发错 usage。

- 删掉：语音、电源（长按）、主页、米家、电影、停止

  已去掉（概览页里那个链接是对的，保留）

## 六、给以后留的笔记

1. **电视不吃某个键，先看 `.kl`**：
   `adb shell cat /system/usr/keylayout/Vendor_2717_Product_32b8.kl`
   —— 里面没有的 Linux keycode 会被静默丢弃，板子日志一切正常但电视没反应。
2. **想知道我们发出的 usage 被认成什么**：`adb shell getevent -lt`。
3. **想知道原装遥控器发什么**：电视上
   `/sys/class/hidraw/hidraw1/device/report_descriptor`（不用 root 就能读；
   但 `/dev/hidraw1` 本身要 root，读不了原始报文）。
4. **⚠ 这台电视的电源键**：短按 = 待机（可唤醒），长按 = 彻底关机（唤不醒）。
   **不要在任何地方做长按电源。**
5. **2026.11 的 HA**：`/api/lovelace/*` REST 端点全 404，面板配置走 WebSocket
   `lovelace/config`（带 `url_path` 选面板）、`lovelace/config/save`。

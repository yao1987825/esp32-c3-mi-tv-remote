# 小米电视蓝牙遥控器 —— 正式版 v1.1.0 发布说明

**发布日期**：2026-11-24
**硬件**：ESP32-C3 SuperMini（USB Serial/JTAG，VID 303A / PID 1001，串口 COM6）
**目标电视**：小米 MiTV4-ANSM0（Android 6.0.1，蓝牙芯片 qca9377）
**固件**：ESPHome / esp-idf / NimBLE（`esphome-ble-mi-remote` 组件）

---

## 这版的行为（用户需求）

| 场景 | 结果 |
|---|---|
| 电视亮屏 → 按板子电源键 | 电视进**关屏待机**（BLE 保持，不断电），**不会再自己醒** |
| 电视待机 → 用原装遥控器 | 电视正常开机（原装遥控器那套机制，完全不受影响） |
| 电视待机 → 按板子任意键 | 板子发唤醒包 → 电视被板子唤醒（`wake_on_press: true`） |
| 电视待机 → 什么也不按 | **电视一直睡着，不会自己开机** ← v1.0.0 的 bug 已修 |

## v1.1.0 修的 bug：电视会自己开机

> 用户反馈：**「为什么我没有按开机，电视自动开机」**

**根因**：`advert_style: mi_wake` 把**唤醒包当成了常态广播包**。
唤醒包里有 `04 FE <电视地址尾3字节>` —— 电视扫到自己的地址就醒。
结果是每一帧广播都在「点名」，**没人按遥控器，电视也会自己开机**。

原装遥控器不会这样：它平时广播的是**不带 `0xFE`** 的常态包，
只在按键那一瞬间才发 3 秒带 `0xFE` 的唤醒包。
参考实现的 README 原话：*「the ESP32 only speaks when asked」*。

**修法**（组件 `ble_mi_remote`）：

| 改动 | 说明 |
|---|---|
| 新增 `buildIdleAdvert()` | **常态包**：结构与唤醒包一致，但**没有 0xFE**、厂商数据字节 `0x00`、UUID 列表 AD type `0x03`（正是原装遥控器常态包的形态）。短名用我们自己的 `MI Remote`，因为电视设备列表只认这个名字 |
| 新增样式 `mi_idle` | **默认样式**：常态广播 = 常态包。旧的 `mi_wake` 样式保留（它就是「唤醒包当常态广播包」= 会让电视自己醒的那个行为） |
| 新增配置 `wake_on_press` | **默认 `true`**：电视待机时按板子任意键能唤醒它（和原装遥控器一样）。设成 `false` 则板子是纯遥控器，待机时按键什么也不做，开机完全由你用原装遥控器搞定 |
| `press()` / `pressSpecial()` | 唤醒广播**只在电视不在线时**才发。电视在线时按键直接过去；在线时发唤醒包反而有害 —— 电源键会把电视关掉，然后我们自己的 0xFE 帧又把它唤醒 |
| `startWakeAdvert()` | 唤醒窗口 10 s → **30 s**。电视待机扫描是**周期性**的，窗口太短会整个错过扫描窗口 |
| `onConnect()` | 电视连回来后**立刻停止**唤醒广播（延迟 300 ms 避开 NimBLE 回调里调 `adv->stop()`）—— 电视都醒了，没必要继续点名 |

v1.1.0 的常态广播（30 字节，**无 0xFE**）：

```
02 01 05              Flags
03 FF 00 00           厂商数据 company 0x0000，payload 00（没按键）
0A 08 4D 49 20 52 65 6D 6F 74 65   短名 "MI Remote"
03 03 12 18           UUID 0x1812 (HID)，AD type 03 完整列表
04 0D 04 05 00        设备类别字段
02 0A 00              TX power 0 dBm
```

按键时才发的唤醒包（31 字节，**与参考实现逐字节一致**）：

```
02 01 05 | 03 FF 00 01 | 06 08 4D 49 20 52 43 | 03 02 12 18
| 04 0D 04 05 00 | 02 0A 00 | 04 FE AA 77 62
```

## 一句话

这版固件让一块 ESP32-C3 板子变成小米电视的**蓝牙遥控器**，并且
**在电视待机时也能把它唤醒** —— 也就是原装遥控器能做到的事，现在这块板子也能做。

## v1.0.0 的核心：待机唤醒

之前板子只能控制「亮着的电视」。这一版解决了「待机中唤不醒」。

### 原理

原装遥控器按电源键时，除了发 HID 键，还会广播一个 31 字节的「点名包」：

```
02 01 05              Flags
03 FF 00 01           厂商数据 company id 0x0000
06 08 4D 49 20 52 43  短名 "MI RC"
03 02 12 18           UUID 0x1812 (HID)，AD type 0x02 不完整列表
04 0D 04 05 00        设备类别字段
02 0A 00              TX power 0 dBm
04 FE AA 77 62        ★ 小米唤醒字段 = 电视自己地址的后 3 字节（逆序）
```

最后那个 `0xFE` 字段就是全部答案：**待机的电视在自己的广播窗口里扫到自己的地址，
就知道「这条是发给我的」，于是唤醒自己并主动连回遥控器。**

我们板子发的是**逐字节一致**的同一个包（`AA 77 62` 来自电视地址
`C8:28:32:62:77:AA` 的后 3 字节逆序）。

> 我们之前**不是发错了字段，是压根不知道有这个字段**。
> 板子自己的嗅探器只打印一张固定 AD type 表，`0x0D` 和 `0xFE` 都不在里面 ——
> 那些字节一直在空中，只是从没被打印出来。

### 实测

2026-11-23 深夜，用当前固件做的完整往返复测（`mWakefulness` 复核屏幕真的亮了）：

```
[  2.8s] pressSpecial: key=5 connected=YES   ← 电视亮着，按电源 → 进待机
[  6.8s] onDisconnect: C8:28:32:62:77:AA
[ 15.7s] pressSpecial: key=5 connected=NO    ← 断链后再按（只发广播）
[ 15.7s] startWakeAdvert: 31 bytes [.. 04 FE AA 77 62]
[ 45.9s] onConnect: peer=C8:28:32:62:77:AA  ← 电视自己连回来
[ 55.2s] 电视活了  mWakefulness=Awake        ★第 1 次唤醒
[ 55.7s] 再按电源 → 又进待机
[ 68.5s] pressSpecial connected=NO
[ 99.7s] onConnect
[102.6s] 电视活了  mWakefulness=Awake        ★第 2 次唤醒
```

**单次唤醒耗时 30~40 秒**（电视待机扫描是周期性的，不是我们发包慢）。
唤醒后持续守候确认：电视不会自己睡回去。

## 电源键的实际行为

| 电视状态 | 按板子电源键 | 结果 |
|---|---|---|
| 亮屏 | 发 HID 电源键 | 电视进**关屏待机**（BLE 保持，不断电） |
| 待机 | 发 HID 电源键 + 唤醒广播（30 秒） | 电视**重新亮屏**（30~40 秒） |
| 待机，什么也不按 | —— | 电视**一直睡着**（常态广播不带 0xFE，不会被点名） |
| 彻底关机（拔电才能恢复） | 任何 BLE 手段都唤不醒 | 硬件限制，原装遥控器也不行 |

开机方式有两条，互不冲突：

1. **用原装遥控器** —— 原装那套机制完全不受影响，照常。
2. **用板子** —— 待机时按板子任意键即可唤醒（`wake_on_press: true`）。
   想让板子彻底不参与唤醒，把这个开关设成 `false`。

## Home Assistant 接入

固件自带 **ESPHome 原生 API**（端口 6053），24 个按键会自动变成 HA 的 button 实体，
**不需要写任何 YAML**。

### 添加步骤（手动）

1. HA → 设置 → 设备与服务 → 添加设备 → 选 **ESPHome**
2. 主机名填 `mi-tv-remote.local`，或直接填 IP `192.168.6.101`
3. 端口 `6053`
4. 粘贴加密密钥（必须和固件里的一致，它就是 API 的 noise_psk）：

   ```
   <你 secrets.yaml 里 api_encryption_key 的值>
   ```

### 添加步骤（脚本，HA 2026.11 专用）

HA 2026.11 把「创建配置流」从 WebSocket 挪到了 **REST**：

```
POST /api/config/config_entries/flow            {"handler": "esphome"}
  -> {"type":"form","flow_id":"...","step_id":"user",
      "data_schema":[{"name":"host"},{"name":"port"}]}

POST /api/config/config_entries/flow/{flow_id}  {"host":"192.168.6.101","port":6053}
  -> {"type":"form","step_id":"encryption_key",
      "data_schema":[{"name":"noise_psk","required":true}]}

POST /api/config/config_entries/flow/{flow_id}  {"noise_psk":"<加密密钥>"}
  -> {"type":"create_entry","result":{"title":"小米电视遥控器","state":"loaded"}}
```

⚠ 两个坑：
- 字段要**直接放在请求体顶层**，不能包在 `{"user_input": {...}}` 里
- WebSocket 的 `config_entries/flow/init` 在这个版本**已经不存在**，一律报
  `unknown_command`

现成脚本：

```powershell
python tools/ha_add_esphome.py --token <TOKEN> --key <加密密钥>
```

> - **固件里实体名保持 ASCII** → entity_id 天然就是 `button.mi_tv_remote_*`

> - **HA 里把设备名改成「小米电视遥控器」** → 设备卡片也是中文
>
> 改名脚本（幂等，可重复跑）：
>
> ```powershell
> python tools/ha_localize.py --token <TOKEN> apply     # 改成中文
> python tools/ha_localize.py --token <TOKEN> revert    # 还原英文
> python tools/ha_localize.py --token <TOKEN> check     # 只看现状 + 查引用
> ```
>
> ⚠ 设备被删掉重新添加之后，要再跑一次 `apply`。

> ⚠ **HA 配置文件要不要改？** —— 实测**不用**。
> 加设备时 HA 自动生成了这 31 个实体，**没有任何自动化或脚本引用它们**，
> 所以改名没有破坏任何东西。以后写自动化时用上面那套 `button.mi_tv_remote_*`
> 的 entity_id 就行。

## 相对上一版的变化

**删掉**了一批试错阶段留下、实测**完全无效**的「唤醒」按钮，免得用的人分不清该按哪个：

| 被删的按钮 | 为什么无效 |
|---|---|
| TV Wake / TV Wake Connect Long（`connect_wake`） | 板子**主动去连**电视 —— 电视待机时根本不接受主动连接 |
| TV Wake Advert / Directed / Named（MiPower 包） | 那是**小米盒子**的协议（company id 0x0046），这台电视不理 |
| TV Wake MI RC / MI RC Own | 被 `mi_wake` 样式取代（含 0xFE 唤醒字段） |

**保留**：`TV Reconnect`（维护用，电视扫不到板子时救命）和 `TV Sniff`（诊断用，
2026-11-23 就是靠它找到了那个 `0xFE` 字段）。

**配置项**：

| 配置项 | 值 | 说明 |
|---|---|---|
| `advert_style` | `mi_idle` | 常态广播 = 常态包（**不带 0xFE**）→ 电视不会自己醒 ★ |
| `wake_on_press` | `true` | 待机时按板子任意键能唤醒电视；设 `false` 则板子是纯遥控器 |
| `target_mac_address` | `"C8:28:32:62:77:AA"` | 电视地址，写死让新刷的板子还没配对时也能发正确的唤醒包 |
| `own_addr_random` | `false` | 备用杠杆，默认关（改身份地址会让 bond 作废） |
| `own_mac` | 注释掉 | 仿冒原装遥控器 MAC 在 C3 + IDF 5.5 + NimBLE 下会触发 host reset，而且会和真遥控器冲突 |

> `advert_style: mi_wake` 这个旧值还在代码里，它就是「唤醒包当常态广播包」=
> 电视会自己醒的那个行为，**不要用**。

## 已知限制

1. **电视彻底关机后唤不醒**（拔电才能恢复的那种）。BLE 主机断电了，
   原装遥控器同样唤不醒 —— 硬件限制，不是板子的问题。
2. **不要用 `adb shell input keyevent 223` 让电视进待机** —— 实测那会让电视进入
   「拔电才能恢复」的状态。日常开关用 HID 电源键短按。
3. **唤醒要等 30~40 秒**，因为电视的待机扫描是周期性的。板子这边发包是连续的
   （20~30 ms 间隔），不是我们慢。
4. **BLE 广播名必须保持 `MI Remote`**。这台电视的蓝牙列表只显示已缓存过的名字，
   改名后在设置页里就扫不到、没法重新配对。
5. 电视**不回 ICMP**，判断死活只能用 ADB 5555。而且电视唤醒后 WiFi/ADB 会话会
   **整个重建**，ADB 客户端里那条 `192.168.6.209:5555` 会变成 `offline` 陈旧条目 ——
   必须先 `adb disconnect` 再 `adb connect`，否则会误判成「电视没醒」。

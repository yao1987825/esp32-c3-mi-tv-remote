## 找到并修复的真 bug（按重要性）

### 1. ★ setSecurityAuth 参数顺序搞错（断联根因之一）
NimBLE 真实签名是 `setSecurityAuth(bonding, mitm, sc)`，
之前误以为是 `(mitm, bonding, sc)`。
- 错误代码 `setSecurityAuth(false, true, false)` → bonding=false → **配对时不存 bond**
- 修复为 `setSecurityAuth(true, false, false)` → bonding=true + Just Works
- 这解释了：`saved bonds=0`、断线无法重连、每次要重新配对

### 2. ★ onDisconnect 里错误删除 bond（断联根因之二）
```cpp
// 旧代码（错误）
if (reason == REM_USER_CONN_TERM) {
    NimBLEDevice::deleteBond(...);  // 电视正常休眠断链就删 bond!
}
```
BLE HID 遥控器休眠时电视**正常**会主动断链，旧代码把这当成取消配对删 bond。
修复：任何断开都保留 bond，统一 `startReconnectAdvert()` 重连。
日志已确认修复生效：`KEEP bond and re-advertise for reconnect`

### 3. 启动崩溃 boot loop（最早修的）
`own_mac` 的 `NimBLEDevice::setOwnAddr()` 在 host 未 sync 时调用 →
`Load access fault` at `ble_hs_init` → boot loop → safe mode。
已禁用 own_mac。注：那条反复出现的 crash 记录
（pc=0x42037488）是历史遗留，标注 "different build"，非当前问题。

### 4. MAC 字节序 bug
`ble_hs_id_set_rnd()` 要 LSB-first，字符串 MAC 是 MSB-first，需反转 6 字节。

### 5. 假日志误导
`is_connected()` 里 `ESP_LOGI("Disconnected")` 每次按键都打，不是真断开事件。
已降为 DEBUG。真正的事件在 `onConnect`/`onDisconnect`（带地址）。

## 走过的弯路（别再重复）

- ❌ **红外方案**：用户明确电视无红外遥控器，纯蓝牙。已删除 IR 配置。
- ❌ **求同广播**（把广播包改成原装遥控器的按键包 `MI RC`）：电视反而扫不到。
  因为原装遥控器平时不发那个包，只在按键时发。已回退。
- ❌ **改名 MI Remote C3**：电视扫不到新名字（只认缓存过的名字）。已改回 `MI Remote`。
- ❌ **WOL / ADB keyevent 223 真关机**：电视进拔电才能恢复的状态。禁用。
- ❌ **盲目改 sc=true/false**：参数顺序错时怎么改都没用。

注意一个小瑕疵（不影响功能）：重连时 `onConnect ... bonded=NO`，

不影响自动重连。如需消除可改为 onConnect 延迟检查。

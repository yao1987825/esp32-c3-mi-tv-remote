# 正式版发布说明 v1.2.1（2026-11-25）

## 一句话总结

**待机时按方向键/音量键也会把电视开机** —— 这不对。现在**只有电源键**能唤醒电视，
其它键在电视待机时什么都不做。

---

## 一、问题现象与诊断

### 用户报告

> 「目前测试之后出现了一个致命的bug，功能基本能用。但是无法使用电源键。
> 其他的按键只要按下都能够触发开机。」

澄清后确认：

> 「待机状态下。电源键按下，自然会开机，但是其他的键为什么按下也能开机」

### 诊断结论：电源键**没有坏**，坏的是「唤醒权限」

实测（板子串口日志 + `adb shell getevent` + ADB 存活状态三方对照）：

| 场景 | 板子日志 | 电视实际反应 | 判定 |
|---|---|---|---|
| 待机 + 按**电源** | `pressSpecial: key=5 connected=NO` → `startWakeAdvert: wake packet (31 bytes) [...] start=OK` → `onConnect` | 开机 | ✅ 正常 |
| 亮屏 + 按**电源** | `pressSpecial: key=5 connected=YES` → `onDisconnect: reason=0x213` | 进待机 | ✅ 正常 |
| 待机 + 按**上** | `pressSpecial: key=1 connected=NO` → **同样的 `startWakeAdvert`** → `queuePendingCommand` → `onConnect` | **也开机** | ❌ 问题在这 |

**根因**：`wake_on_press: true` 的语义是「电视不可达时，按任意键都发唤醒广播」。
实现上 `press()` / `pressSpecial()` 的**断连分支里，`startWakeAdvert()` 对所有键一视同仁**，
电源键唯一的区别只是「唤醒后不补发该键」：

```cpp
if (this->_wake_on_press) {
    this->startWakeAdvert();      // ← 所有键都会走到这里
}
if (k == SPECIAL_POWER) {
    // 电源键不排队补发（避免刚唤醒就被自己关掉）
} else {
    this->queuePendingCommand(k, true);
}
```

所以「方向键也能开机」不是偶发 bug，是这个设计的直接结果。

## 二、修复

### 组件：新增 `wake_keys:` 配置

只有**列出来的键**在电视待机时才允许发唤醒广播；其余键在待机时
**什么都不做**（不发唤醒包，也不排队补发）。

```yaml
ble_mi_remote:
  wake_on_press: true
  wake_keys:
    - Power        # 只有电源键能唤醒电视
```

- `wake_keys:` **不写** = 任意键都能唤醒（老行为，和原装遥控器一样）
- 内部用位掩码实现（bit N = special key N），0 = 不限制

改动文件：

| 文件 | 改动 |
|---|---|
| `components/ble_mi_remote/ble_mi_remote.h` | `set_wake_keys()` / `wakeKeyAllowed()` / `_wake_keys_mask` |
| `components/ble_mi_remote/ble_mi_remote.cpp` | `press()` 和 `pressSpecial()` 的断连分支加闸门 |
| `components/ble_mi_remote/const.py` | `CONF_WAKE_KEYS` |
| `components/ble_mi_remote/__init__.py` | `validate_wake_keys()` + 配置项 |
| `esp32-adb-remote/esphome/tv-remote.yaml` | `wake_keys: [Power]`，版本 1.2.1 |
| `tools/verify_wake_only_power.py` | **新增**：自动回归脚本 |

### 现在的行为

| 场景 | 结果 |
|---|---|
| 待机 + 电源键 | ✅ 电视开机 |
| 待机 + 方向键 / 音量键 / 确认键 / 返回键 | ✅ **电视毫无反应** |
| 亮屏 + 电源键 | ✅ 电视进待机 |
| 亮屏 + 其它键 | ✅ 正常导航 / 调音量 |

## 三、其它说明

- **v1.2.0 的改动全部保留**：确认键修复（键盘页 usage 0x28 → DPAD_CENTER）、
  9 个按键白名单、删语音键、删「电源（长按）」。
- **想恢复「任意键都能唤醒」**：把 YAML 里 `wake_keys:` 那两行删掉，重新编译烧录即可。
- **长按电源仍然绝对不要用**：长按 = 电视彻底关机 = BLE 唤不醒（只有拔电源能恢复）。

## 四、给以后留的笔记

1. **电视不吃某个键，先看 `.kl`**：
   `adb shell cat /system/usr/keylayout/Vendor_2717_Product_32b8.kl`
   —— 里面没有的 Linux keycode 会被静默丢弃，板子日志一切正常但电视没反应。
2. **想知道我们发出的 usage 被认成什么**：`adb shell getevent -lt`。
3. **想知道电视是醒着还是待机**：`adb disconnect` + `adb connect`，
   连不上 = 待机（注意必须先 disconnect，不然会拿到 offline 的陈旧条目）。
4. **⚠ 这台电视的电源键**：短按 = 待机（可唤醒），长按 = 彻底关机（唤不醒）。
5. **2026.11 的 HA**：`/api/lovelace/*` REST 端点全 404，面板配置走 WebSocket
   `lovelace/config`（带 `url_path` 选面板）、`lovelace/config/save`。
